# Qiita CLI を使って記事投稿の第一歩を踏み出してみた

## はじめに

初めまして。都内で SES をしている WEB エンジニアです。
エンジニア歴 3 年目にしてようやく「記事投稿」なるものをしてみようと思い、今回 1 本目を書き始めました。
目的は自身のスキルアップ、知見共有、そして暇つぶしです。「記事投稿」がスキルアップに有効かどうかは賛否両論あると思いますが、自分みたいな**食わず嫌い**にとっては「とにかく一本出してみるか」、といった感じです。

また、自分は 0 から 1 を生み出すのが苦手なので、要所要所で AI の力を借りていますが、1 本目の記事は「記事を出す」ことに意味があると思うので、未熟でも AI に頼っても「とにかく記事を出す」ことが重要かと思います。

今回の記事が誰かの役に立てれば幸いです。

### この記事でできること

この記事を読むことで、以下のことができるようになります。

- Qiita CLI を使って記事を投稿できるようになる
- 初めての記事投稿のハードルを下げられる
- 記事投稿の第一歩を踏み出せる

## 対象読者

- 記事投稿をしたことがない人
- 記事投稿に興味はあるが、第一歩が踏み出せない人
- Qiita CLI を使って投稿することに興味がある人

## Qiita CLI とは

Qiita CLI とは、手元の環境で記事の執筆・プレビュー・投稿ができる Qiita が提供している公式ツールです。
作成した Markdown ファイルをコマンドで投稿できるため、エンジニアとして慣れ親しんでいるエディタを使って「コーディング」のように記事を書くことができます。
GitHub Actions による自動投稿もサポートしているので、「記事投稿」ではなく「コミット」や「PR のマージ」といった、エンジニアの日常作業寄りの操作にすることで、「記事投稿」へのハードルが下がるのではないかと思います！

詳細は公式記事をご参照ください：[自分のエディタで記事投稿ができる、Qiita CLI の使い方](https://qiita.com/Qiita/items/666e190490d0af90a92b)

## 環境・前提

- PC
- .md ファイルを編集するための任意のエディタ（VSCode、Vim など）
- Node.js 18.0.0 以上
  - Node.js のインストール方法は[公式サイト](https://nodejs.org/ja/)を参照してください
  - インストール済みかどうかは `node --version` コマンドで確認できます

## 手順

### 1. Qiita にログイン（サインアップ）する

Qiita にログイン、または新規登録してログインします。
Qiita は GitHub、Google、X（Twitter）での OAuth（ユーザーのパスワード情報を他のサービスに渡さずに、外部のアプリケーションにアクセス権を与える仕組み）をサポートしているので、アカウント作成自体はかなり簡単に行えます。

### 2. メールアドレスを認証する

Qiita に記事投稿するためには、メールアドレス認証を行う必要があります。
設定を保存すると、登録したメールアドレスに認証メールが飛んでくるので、そこにあるリンクをクリックすれば OK です。<br>
※通知設定はお好みでチェックしてください。自分は通知が苦手なので、「編集リクエスト」「リンク」「いいね」以外はすべて外しました

### 3. Qiita CLI による記事投稿

※ここからは上記で紹介した、Qiita CLI の使い方の記事に書かれていることとほぼ同じです。

#### 3.1 Qiita CLI のインストール

```
npm install @qiita/qiita-cli --save-dev
```

#### 3.2 Qiita CLI のセットアップ

下記のコマンドによって初期化することで、

- .gitignore
- GitHub Actions のワークフローファイル
- ユーザー設定ファイル（qiita.config.json）
  が生成されます。

```
npx qiita init
```

#### 3.3 Qiita CLI のログイン

下記のコマンドから Qiita CLI のトークン発行画面へ飛び、トークンを生成して登録を行います。

```
npx qiita login
```

## ハマったポイント

PC に Node.js を入れたくなくて、Docker を使ってコンテナから作業していたところ、`npx qiita preview`でプレビュー画面が表示できず、詰まってしまいました。

ブラウザで `localhost:8888` にアクセスしても「接続できません」と表示され、コンテナ内では正常に起動しているのに、ホスト側からアクセスできない状態でした。

本来「投稿すること」に集中すべきところ、他の部分で脱線してしまい、危うく本筋の「投稿すること」が達成できなくなるところでした。
まずは MVP として世に出すことがいかに大切か、身に染みて実感しました...
（こうやってハマったポイントとして書くことができたので、結果オーライではありますが）

<details><summary>解決策</summary>

解決策としては、以下の 2 点を実施しました。

1. `qiita.config.json`に`host`を設定する項目があるので`0.0.0.0`を設定する
2. Docker のポートマッピングを`8888:8888`でコンテナ側とローカル側で正しく設定する

これにより、ホスト側のブラウザからプレビュー画面にアクセスできるようになりました。

`qiita.config.json`の設定例：

```
  "includePrivate": false,
  "host": "0.0.0.0",
  "port": 8888
```

</details>

## 任意だけどおすすめのこと

- VSCode に markdown のフォーマッタをインストールし、保存時に自動フォーマットをかける
  → 記述スピードのアップとストレスの軽減につながります

- ドラフトの作成
  → 初めの一歩は何を書いていいか、どう書いていいか分からないので、AI におすすめのジャンルや書き方のドラフトを出力してもらい、そのフォーマットをコピペして書き始めました

- まるっとリポジトリ管理
  → 自分は Git でコミットが積みあがっていくのが好きなので、今回の技術記事自体もリポジトリ管理することにしました。

## まとめ

下書きに沿って本記事を執筆していますが、実際は下記のような流れで書いていました

- Qiita CLI を使った記事投稿手順の確認（公式ページ）
- ChatGPT に相談して、ジャンルとドラフトの相談
- ドラフトをもとに Markdown ファイルを用意
- 「タイトル」、「対象読者」、「はじめに」を書き始める。後はハンズオンしながら追記していく
- 完成した Markdown ファイルを AI（自分は Cursor）に投げて、添削してもらう
- 最後に Qiita CLI で記事投稿して終了

記事の構成やコンテンツが、記事投稿初心者の最も悩めるポイントだと思うので、そこら辺を AI に投げることで、まずは「記事投稿」へのハードルを下げることが有効だと思います！<br>
（あまり多用すると「自身のスキルアップ」や「知見の共有」といった目標とズレてしまうので、距離感には気を付けていきましょう）
